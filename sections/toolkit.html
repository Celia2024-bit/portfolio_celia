This started as one tool, not four. Building my own C++ trading system, the bugs that cost me the most were the silent ones — memory creeping up, thread count growing, handles never released. Nothing crashes; hours later the system falls over and there is no stack trace to read. Happy-path tests are far too short to catch that. The fix was to stop watching thresholds and start watching slopes, which became the performance monitor.

Then the same shape of problem kept reappearing somewhere else — work that was mechanical, repetitive, and easy to get subtly wrong by hand. Each time I wrote the tool instead of doing it again. They ended up sharing one rule: anything that edits your source code has to be able to put it back exactly as it was. A tool you cannot undo is a tool you will not run on code you care about.

Aspect Injector walks the Clang AST to add tracing, parameter validation and exception guards, then strips them again byte-for-byte. State Machine Toolkit generates the C++17 state machine and its Mermaid diagram from one definition, so the diagram cannot drift from the code. Interface Sync scans the header tree to propagate a changed signature through every implementation. And the Performance Monitor is the one that watches the result — sampling memory, threads, handles and context switches, fitting a slope over the trend, and blocking the merge in CI when the slope points up.
